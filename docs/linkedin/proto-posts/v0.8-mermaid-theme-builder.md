# LinkedIn Proto-Post v0.8: Mermaid Theme Builder and the Visual Governance Gap

**Status:** Proto-post for review

**Release:** v0.8
**Primary angle:** Mermaid Theme Builder as a concept incubator for inconsistent AI-generated diagram styling

## Draft post

AI made Mermaid structure cheap.

It did not make visual consistency cheap.

I could ask different AI tools for the same diagram and get outputs that were all technically useful, but visually unrelated. Colors drifted. Typography drifted. The same styling choice worked in one renderer and disappeared in another.

The diagram was not necessarily wrong.

The visual contract was missing.

That gap became Mermaid Theme Builder.

It started as a firsthand response to the frustration of repeatedly fixing AI-generated Mermaid output. It has grown into a concept incubator for visual governance: paste Mermaid, detect the diagram family, apply a reusable palette, preview the result, and export renderer-aware code or prompt scaffolding.

It is deliberately not a diagram editor. It does not replace the thinking that creates the structure. It governs the layer that comes after structure: how the diagram should look, where that look will survive, and how to give the next AI generation a better visual contract.

That distinction matters because AI-generated diagrams have at least two failure modes:

- The structure does not represent the idea.
- The structure is useful, but the visual output is inconsistent or fragile.

The first problem is where *The First Diagram Is Usually a Liar* began.

The second problem is what Theme Builder is now testing.

Try it, break it, and tell me where the visual contract still fails.
