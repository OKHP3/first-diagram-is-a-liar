## Post

AI made Mermaid structure cheap.

Visual consistency still sends an invoice.

I gave ChatGPT, Claude, Gemini, Perplexity, and Copilot the same diagramming instructions. They produced different diagrams. I expected that.

What surprised me came later: supplying the same Mermaid code brought the results much closer, but the colors, fonts, and line treatment still did not look like one corporate diagram set.

I wanted a way to apply a consistent visual style to an existing diagram. And when I stumbled onto a theme I liked, I wanted to bottle that lightning for the next one.

Then came the HTML/CSS thought: what if the prompt came with a reusable style file? Give the AI the diagram brief AND the styling expectations.

That became Mermaid Theme Builder: a workbench for applying reusable palettes and typography to Mermaid code, previewing the result, and exporting styled code or prompt scaffolds with a target renderer in mind.

It does not decide what the diagram means. And renderer-aware does not mean renderer-proof. The destination still needs checking.

The hindsight? Had I learned about Agent Skills a month earlier, I might have started by packaging the instructions, theme assets, and styling checks as a skill.

A skill could carry the recipe. The renderer would still have to cook it.

See the live project and its current scope: https://overkillhill.com/projects/mermaid-theme-builder/

If you maintain Mermaid diagrams, where does consistency break first: palette, diagram family, or renderer?

## Optional first comment

Want to inspect the implementation? The public repository includes the source and renderer profiles: https://github.com/OKHP3/mermaid-theme-builder

Mermaid supports theme configuration, including colors and fonts. The CSS comparison describes the idea of reusable styling; an adjacent stylesheet is not automatically loaded by every Mermaid host.

An Agent Skill can package instructions, assets, and scripts for the workflow. Applying the theme and checking the destination renderer would still be part of the job.
