## Post

AI made Mermaid structure cheap.

Visual consistency still sends an invoice.

Different AI tools can produce useful Mermaid diagrams with palettes and typography that drift. Then a diagram that looks right in one preview can change in the place you actually need it.

That gap became Mermaid Theme Builder.

Bring Mermaid code. Choose a reusable palette and typography, preview the result, select a target renderer, inspect compatibility advisories, and export styled code, a Markdown bootstrap, or a prompt scaffold.

It governs the visual layer around a diagram you already have. It is not a diagram editor: it does not decide what the diagram means or fix its structure. And renderer-aware does not mean renderer-proof. Profiles can flag known limits; host support and Mermaid versions still vary. Check the destination where the diagram will live.

In this release series, v0.6 covered Notion as the working record. v0.7 covered Replit as a build environment. v0.8 turns to visual governance. Next, v0.9 looks at process semantics with BPMN for Mermaid. Related problems, different layers.

Try the tool: https://okhp3.github.io/mermaid-theme-builder/

Project page: https://overkillhill.com/projects/mermaid-theme-builder/

If you maintain Mermaid diagrams, where does consistency break first: the palette, the diagram family, or the renderer?
