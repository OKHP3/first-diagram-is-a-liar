# LinkedIn Proto-Post v0.9: BPMN for Mermaid and the Missing Process Layer

**Status:** Proto-post for review

**Release:** v0.9
**Primary angle:** BPMN for Mermaid as a concept incubator for connecting written process steps to useful visual models

## Draft post

Writing the process is not the same as seeing the process.

That became obvious every time I asked an AI tool to turn business-process language into a diagram.

The result might be readable. It might even render cleanly. But a generic flowchart can erase the things that make a process a process: roles, events, gateways, handoffs, service tasks, and the difference between sequence flow and message flow.

Mermaid is excellent at making diagram-as-code approachable. It does not yet give every business process the visual vocabulary it deserves.

That gap became BPMN for Mermaid.

The concept incubator is a text-first `bpmn-beta` DSL: readable in a Markdown code fence, understandable to people, generatable by AI, and preservable in Git. Around it sits a live playground, a parser and SVG renderer, a DSL reference, architecture notes, and a 15-skill business-process suite for collecting the written work that should come before and after the diagram.

The important part is the connection:

Written process narrative → structured process model → diagram visualization → review and handoff.

This is not a claim that a prototype is a complete BPMN 2.0 engine. It is a test of whether we can create a lighter, more inspectable path from business language to process visualization without forcing every contributor into XML or a heavyweight modeling tool.

The first diagram can lie because the structure is wrong.

It can also lie because the structure is too weak to carry the meaning of the written process.

What business process do you wish your AI tools could model without flattening it into a generic flowchart?
