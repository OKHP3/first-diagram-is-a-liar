## Post

Writing the process is not the same as seeing the process.

An AI can turn a paragraph into a tidy flowchart. But tidy boxes can hide the things that make a business process a process: who does the work, where decisions branch, and how handoffs happen.

Mermaid makes diagrams approachable as text. Its standard flowchart syntax does not provide a dedicated vocabulary for those process concepts.

That gap became BPMN for Mermaid.

The project is testing a small, readable `bpmn-beta` language for describing process structure in text, then rendering a visual model in a browser playground. The source can live beside the rest of a project in Git. A contributor can inspect the words, the structure, and the rendered result.

The path is simple:

Process narrative → structured model → diagram → review.

The boundary matters. This is a prototype and diagram-type contribution proposal. It is not a production Mermaid plugin, a complete BPMN 2.0 implementation, an XML import/export tool, or an executable process engine. Message flows and cross-pool routing are experimental and need checking in the playground.

The first diagram can lie because the structure is wrong. It can also lie because the notation cannot show what the process actually means.

What gets lost when your process becomes a generic flowchart?

Try the playground: https://okhp3.github.io/mermaid-diagram-bpmn/
