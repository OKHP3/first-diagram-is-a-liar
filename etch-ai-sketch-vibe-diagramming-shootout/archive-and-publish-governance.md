# Archive and Publish Governance

## Boundary

The council repository is the evidence archive. The OverKill Hill repository
is the production web source. This Replit workspace contains API and component
preview artifacts; those artifacts are not the deployment target for the
external article.

Do not imply that a running API or mockup workflow publishes
`overkillhill.com`. The production URL is canonical only after external
deployment has been verified.

## Archive contract

Each member folder may contain:

1. `README.md` — role, conditions, contribution, and links;
2. `v1-diagram.md` and/or `v2-diagram.md` — preserved source and notes;
3. provider links or asset notes, clearly labelled as external.

Do not invent missing deliberations, voting records, or model conditions.
When an entry is late, specialty, exhibition, or excluded, keep that status
visible in the member README and canonical story.

## Publication record

Before a public release, record:

- release identifier and date;
- source repository and commit/ref;
- external deployment result;
- canonical URL and HTTP result;
- social image and metadata result;
- Mermaid render/link result;
- analytics debug result;
- rollback checkpoint or previous release identifier.

The release is ready only when source preparation, external deployment,
canonical verification, social preview, and rollback evidence are all present.

## Rollback

Rollback means returning the external production repository to the last
verified source snapshot. Do not delete archive evidence to make a release
look cleaner. Preserve the failed release notes and link checks for diagnosis.
