The First Diagram Is Usually a Liar

A diagram is not a picture of the work. It is a claim about the work. Make the claim earn its arrows.

Read the article → View on GitHub Open the archive

Delivery note: The interactive tutorial is implemented in this repository, but its GitHub Pages URL is not presented as live until the deployment workflow and a live smoke test succeed.

Why this exists

The tidy diagram is often the expensive one.

People draw the first diagram that makes their own thinking feel orderly. That diagram can hide loops, dead ends, unresolved choices, ownership gaps, and revision history. The next person then pays the reconstruction tax.

This project teaches a practical alternative: expose the claim, measure whether the visual removes confusion, show the disagreement, and ship the receipts with the result.

Working principles

Structure is a product decision.

01

Structure is the product

The shape of the visual changes what a reader believes about the work.

02

Revision is evidence

A better diagram should show what changed and why.

03

Conditions come first

Tool, prompt, role, and round matter before any comparison.

04

Humans own the claim

AI can challenge a representation. It does not own the underlying truth.

05

Receipts survive failure

If a CDN or renderer fails, the source and explanation remain useful.

Scope boundary

What this is not.

It is not an AI diagram generator.

It is not a visual editor or a Mermaid hosting service.

It is not a scientific measurement system.

It is not a ranking engine for AI providers.

It is not a backend application or data collection service.
